## What an item-8 `met` means here — read this before reading the table above

**It means: an aggregated, current, per-spec-row characterization artifact
exists, and a human re-read it against a named commit.**

**It does not mean this block meets its spec. It does not.** Three ratified
rows FAIL in the very document these two citations wrap:

| Area | < 0.1 mm² | **0.150536 mm²** as built | FAIL |

…and the digital partition's rung-2 gate-level SPICE replay is not passing
either. **Whether the block passes its corner set is T1 item 5**, which is
`unmet` on both partitions in the report above and stays that way. The
checklist separates "is there a current characterization report?" from "does
the block pass?" deliberately, and this record is the place that separation
has to be said out loud, because a reader scanning a row of green is exactly
who would otherwise get it wrong.

This is the same discipline the superseded record applied to item 6: a `met`
there means "one passing yield envelope was cited and is fresh", which is
narrower than the item's own text. Here, `met` means "a report exists and is
current", which is narrower than "the numbers in it are good".

### The envelope, and why there are two of them

T1 item 8 is the only checklist item that names no `klt` verb. No verb's
output can satisfy it structurally, because what it asks for is a
*hand-assembled aggregation*; `klt signoff` ingests one through an opt-in
**generic evidence envelope** (`"kind": "generic"`, klayout-tools#1152), and
item 8 is the only item that accepts one — since klayout-tools#2044 it
accepts `generic` and **nothing else**.

Two envelopes were written, not one:

| File | Asserts | Partition |
|---|---|---|
| [`../evidence/characterization-summary.analog.json`](../evidence/characterization-summary.analog.json) | the per-spec-row table | analog |
| [`../evidence/characterization-summary.digital.json`](../evidence/characterization-summary.digital.json) | the `sar_ctrl_a` Fmax/area/power section | digital |

Both wrap — and both pin the sha256 of — `sim/characterization-summary.md`.
They are two files because **this manifest keys every citation per
partition** (its own `_comment` explains why at length), and because the two
halves assert different things about different silicon. One shared envelope
would have made the digital row's verdict a restatement of the analog row's,
which is precisely the conflation the per-partition keying exists to prevent.

They live in a new `signoff/evidence/` directory — **the one exception to
"this directory stores no evidence of its own, only citations to it."** Every
other citation in this manifest points at a JSON envelope some `klt` verb
produced as a by-product of doing real work. These two are written by this
repo, for the grader, because item 8 has no verb behind it.
[`../evidence/README.md`](../evidence/README.md) states that exception, what
a `pass` there does and does not mean, and the order in which a future
re-assertion has to happen (**re-read first, JSON second** — the JSON is the
receipt, the re-read is the work).

## Method

```bash
pip install 'git+https://github.com/2AMLogic/klayout-tools@67d617f899c7fb941b86cfc85491f75b91ae1176'
python3 signoff/run_signoff.py --regen      # runs the grader, mints the report
python3 signoff/run_signoff.py --check      # re-derives it with no klt at all
python3 signoff/run_signoff.py --selftest   # negative control, 9 tampered inputs
```

### The freshness hole a generic citation opens, and how it is closed

For every **native** kind the grader knows which field names the input that
run consumed (`drc`/`extract`/`erc` → `file`, `lvs` → `layout`, `sim` →
`netlist`, `sta` → `def_path`, `yield` → `samples`), so it re-hashes the
artifact itself and reports `input_verified: true|false` (klayout-tools#2196).
**A `generic` envelope's author picks their own field names**, so the grader
cannot know what to re-hash and reports `input_verified: null` — the
manifest's pinned hash was only ever compared against the envelope's *own
claim* about the document. Both item-8 rows in the committed report say so
in as many words:

```
input: not re-hashed (content_hash compared against this envelope's own claim only
       -- the artifact itself was not read)
```

That leaves exactly one rot path: edit `sim/characterization-summary.md`,
leave the envelope and manifest alone, and the grader goes on rendering `met`
forever over a document that no longer says what was asserted about it.

**`--check` closes it from the repo side**, the same way it already does for
the digital DRC citation: `sim/characterization-summary.md` is pinned under
both item-8 citations' `artifacts`, and CI re-hashes the committed file on
every pull request with nothing but CPython. As with `3.digital`, the
repo-side check here is **strictly stronger than the grader's**.

### Negative control (new, and why it was added)

`signoff/evidence/README.md` and the wrapped document both state outright
that *"editing this document without re-running `--regen` turns CI red."*
**That is a claim, so it gets a testbench** (CLAUDE.md: no claim without a
testbench). `--selftest` grew a control per generic citation:

```
[ok] caught: the record behind generic citation 8.analog (sim/characterization-summary.md)
             was edited without `--regen`
[ok] caught: the record behind generic citation 8.digital (sim/characterization-summary.md)
             was edited without `--regen`
```

It is deliberately distinct from the pre-existing
`"a cited artifact's bytes changed"` control, which tampers with whichever
citation sorts first (`3.analog`, a native envelope). The new one is keyed on
the `generic` kind specifically, and it **raises rather than skipping** if no
generic citation is found, or if a generic citation pins no artifacts — so it
cannot go quietly vacuous if item 8's citation is ever removed or re-pointed.
Nine tampered inputs now, all caught; the control run (an untampered overlay)
still passes.
