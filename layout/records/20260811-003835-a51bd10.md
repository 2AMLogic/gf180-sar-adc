## Method

`design-evidence-tiers.md`'s own rule: *"Staleness is failure. Every report
is checked against current source revisions/hashes before it counts."* This
repo's `layout/{drc,lvs}/run_*.py` stamp `repo_git_sha` and `repo_dirty`
into each record's `toolchain.json`/`records/*.md`, but a run executed from
an **uncommitted** working tree (`repo_dirty: true`) stamps the *parent*
commit, not the commit the change eventually became -- confirmed directly
while producing this record: the latest DRC/LVS record pair
(`20260806-233236-56be937` / `20260806-233251-56be937`) both stamp
`repo_git_sha: 56be937...` with `repo_dirty: True`, yet their own result
tables already describe the comparator's issue #118 resistor markers, which
landed in the *next* commit, `6c2b41c` (2026-08-07T00:02:41Z, ~90 seconds
after `56be937`'s LVS record timestamp) -- i.e. the run executed against a
local, not-yet-committed edit that was committed moments later. **Git-sha
ancestry alone is therefore not a reliable freshness check for this repo's
evidence trail.** This record instead recomputes SHA-256 directly against
every currently-committed GDS (DRC) and extracted-netlist `.spice` file
(LVS) under `layout/adc-top/`, `layout/drc/cells/`, and `layout/lvs/cells/`,
and compares that independently-computed digest against each report's own
`provenance.input.content_hash` (DRC) or `environment.layout_sha256` (LVS).
A report is marked **fresh** below only when that comparison matches byte
for byte.

### DRC deck coverage gaps

Read from the latest run's `coverage.rules_skipped` /
`coverage.layers_in_stream_without_rules` fields (not from the narrative
text alone):

- **`rules_skipped`** on every cell includes `bjt.separation.comp.1`,
  `metaltop.space.1`, `metaltop.width.1`, `pad.enclosing.metal5.1` -- rules
  the deck defines but that never evaluate because this design draws no
  BJT, MetalTop, or bond-pad geometry. Not a gap in what was *checked*
  against what exists; a rule with nothing to check is not a hole.
- Leaf cells (`adc_drv`/`adc_tgate`/`adc_tgate_dum`/`adc_tp_sw`/
  `comparator`/`comparator_nores`/`sw_unit`) additionally skip the full
  Metal2-5/Via1-4/MiM rule set for the same reason (no metal stack above
  Metal1 drawn at leaf level) -- expected, and already the documented
  reason `layout/README.md`/`layout/adc-top/README.md` give for why a
  clean leaf-cell report "says NOTHING about the MiM capacitor stack" on
  its own (only the block-level `adc_top`/`adc_block` reports, which do
  draw the full stack, close that claim).
- **`layers_in_stream_without_rules`** on `adc_block`/`comparator`:
  `34/10` (Metal1 pin-label layer, used by the LVS flow, not a DRC-checked
  physical layer), `49/0`/`62/0`/`110/5` (SAB/Resistor/RES_MK -- issue
  #118's poly-resistor device markers), `117/5`/`117/10` (label/text
  layers). None of these are DRC-relevant shapes; the deck correctly has
  no width/space rule for a marker or label layer. Recorded here because
  `design-evidence-tiers.md` requires deck holes to travel with the claim
  even when, as here, they resolve to "not a hole" on inspection.
- **Deliberate, already-documented layout gap, not a DRC-report gap**: the
  SAR-logic sequencer (per `layout/adc-top/README.md` line ~160, DR-0010)
  is **not drawn** -- "there is no transistor-level netlist to place" at
  the open gf180mcu PDK's rung-1 ceiling -- so it carries no DRC (or LVS)
  report at all, by design, not by oversight. The reserved+ringed area is
  itself the deliverable at this rung.

  report's warning count is what makes "every PMOS body in the block is
  remediated" a checked statement per `run_lvs.py`'s own docstring, not an
  assumption.
- **Unmodelled poly-as-interconnect shapes** -- poly-layer shapes that
  touch Contact at two-plus points with no resistor marker are
  indistinguishable from a drawn resistor body to this deck and get
  absorbed into ordinary interconnect; the count is pinned per-cell as a
  regression test on the router, per `run_lvs.py`'s `_check_warnings`
  docstring.
- **Net-to-pin promotion notices** -- internal nets promoted to top-level
  pins from sub-cell labels on the two block cells; a naming/visibility
  notice, not a connectivity defect.

None of these are LVS mismatches (the LVS `status`/`mismatch_count` fields

`design-evidence-tiers.md`'s coverage-honesty rule asks to travel with the
claim regardless.
