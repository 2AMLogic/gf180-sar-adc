## What changed, and why

Issue #338: item `4.analog`'s citation
(`layout/lvs/reports/20260817-185722-40cfeb8/adc_block.lvs.json`) was the one
citation in this manifest with no `content_hash` — mechanically, not by
judgement, because that report was written by `klt 0.2.0`
(`layout/toolchain.json`'s then-pin, `85b8125`), which did not populate `klt
lvs`'s `provenance.input` at all. Pinning a hash against a `null` field would
have rendered a fresh report `unmet`/`stale_evidence`, a false negative, so
`signoff/freshness.json` carried a `manifest_pin_note` explaining the gap and
pinned freshness repo-side instead (`environment.layout_sha256`/
`reference_sha256`).

**This is closed, not merely worked around.** `layout/toolchain.json` is
bumped to `b15edf5e` (upstream `main` HEAD as of 2026-09-21), which is past
both `klayout-tools#1969` (PR #2005, populates
`provenance.input.content_hash`) and `klayout-tools#2027` (PR #2058, adds the
`input.role` field so the hash's *kind* — layout stream vs. pre-extracted
netlist — is machine-readable rather than assumed), absorbed in one bump per
#338's own scope. See `layout/toolchain.json`'s own `_comment` ("THE ISSUE
#338 PIN") for the full accounting of what that bump does and does not move
(`layout/lvs/cells/cells.json` needed re-baselining on three axes, all
connectivity-preserving; `layout/drc/cells/cells.json` needed none).

The block was re-extracted and re-compared under the new pin
(`layout/lvs/run_lvs.py --regen`, evidence record
[`layout/lvs/records/20260921-175027-93ddfe3.md`](../../layout/lvs/records/20260921-175027-93ddfe3.md)),
minting `layout/lvs/reports/20260921-175027-93ddfe3/adc_block.lvs.json`:
`status: match`, `mismatch_count: 0`, same 198/198 nets, 1349/1349 devices,
71/71 pins as the superseded report — **this bump changes what is graded, not
what is measured.** Its `provenance.input` now reads
`{"content_hash": "sha256:fa2bf591…d6eb1", "role": "netlist"}` (the pre-extracted
`layout.netlist` request shape this repo uses hashes the SPICE netlist `klt
lvs` compared, not a layout stream — exactly the distinction
klayout-tools#2027 makes explicit via `role`). The manifest now cites that
report with `content_hash: sha256:fa2bf591…d6eb1`, `klt signoff --manifest`
grades it on that hash directly, and `signoff/freshness.json`'s
`manifest_pin_note` for this citation is gone — no repo-side workaround
