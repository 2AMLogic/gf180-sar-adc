### Negative control

A check nobody has watched fail is not evidence that it can fail.
`run_signoff.py --selftest` builds sandboxed copies of exactly the files
`--check` reads, tampers with one input in each, and asserts `--check` fails:

1. a cited artifact's bytes changed (the DRC/LVS-rot case);
2. a cited envelope's own `status` changed;
3. the committed report's row verdict changed;
4. the committed text rendering (`signoff.txt`) was hand-edited;
5. the manifest grew a citation `freshness.json` does not declare;
6. an **existing** citation was re-pointed at the other partition's
   envelope, with `freshness.json` updated to match;
7. the upstream checklist's text hash moved.

All seven are caught, and an untampered control passes.

**Case 6 is the one that matters most and the one that was missing.** It is
the exact hand-edit the manifest's `_comment` warns against — re-point
`3.analog` at the *digital* partition's DRC envelope, update every repo-side
pin in `freshness.json` to match, skip `--regen` — and it would have left the
manifest standing a routed digital macro's DRC as the analog partition's
evidence, which is the conflation the per-partition keying exists to prevent.
Every repo-side pin agrees with itself in that state, so cases 1–3 and 5 see
nothing wrong; only the committed report still remembers what the row was
graded on. `--check` now compares each row's `citation.file` and
`citation.content_hash` — recorded by the grader at grading time — against the
manifest, which closes it. (Found in review of the pull request that landed
this record; the report itself is unchanged by the fix, and `--check` still
returns the same verdict.)

**The one row that comparison cannot reach** is `7.analog`: its `klt pex` run
errored, so the grader renders `citation: null` and the report never records
which file it read. That gap is declared in `freshness.json` under
`report_citation_note` rather than skipped silently — `--check` fails any
cited item whose row renders no citation unless its freshness entry says why.

## Block kind: `mixed-signal`, and where the partition boundary runs

A T1 claim states the block's kind, and a `mixed-signal` claim must state the
partition boundary explicitly — "which nets/pins/cells belong to which side" —
so a reviewer can tell which evidence covers which silicon.

**This block is `mixed-signal`, which changes the kind the 2026-08-25 hand
re-read recorded (`analog`).** That read was correct when taken: the SAR
sequencer then existed only as DR-0010's rung-1 ideal-XSPICE behavioural
model, with no RTL, no gate netlist and nothing drawn, and the re-read
disclosed that as a scope boundary rather than claiming the digital column.
Between then and this record the digital partition became real:

- `design/sar-logic/rtl/sar_ctrl.v` — synthesizable RTL (`sar_ctrl_a`), #272.
- `design/sar-logic/flow/sar_ctrl/netlist/sar_ctrl.mcu7t5v0.synth.v` — the
  synthesized gate-level netlist, with `klt synthesize` and equivalence
  request/response documents beside it.
- `design/sar-logic/flow/sar_ctrl/reports/*.sta_*.json` — per-corner `klt sta`
  runs, pre- and post-route.
- `layout/adc-top/sar_ctrl/{sar_ctrl.def,sar_ctrl.gds,sar_ctrl.v}` — the
  placed-and-routed macro from `klt place-and-route`, #274.

Declaring `analog` today would take eleven digital-column rows off the report
entirely. The consequence of declaring `mixed-signal` is a longer report with
more unmet rows, which is the correct direction for a grader to move a claim.

**The boundary is the 71-net interface between `sar_ctrl_a` and `adc_block`**,
and it is a hard one: the two partitions are separate GDS streams that have
never been merged.

| Side | Contents | Physical artifact |
|---|---|---|
| **Analog** | CDAC array (1024 unit MiM caps), bottom-plate T-gates and their drivers, top-plate `V_cm` switch, input sampling structure, comparator (+ load resistors) | `layout/adc-top/adc_block.gds` — 323 transistors + 1024 caps, 71 pins |
| **Digital** | Bit-cycle sequencer, CDAC switch decode, 10-bit parallel output register — `sar_ctrl_a` | `layout/adc-top/sar_ctrl/sar_ctrl.gds` — routed standard-cell macro |

Signals crossing it, by name:

- **Digital → analog**: the one-hot CDAC controls
  `rel_n_*`/`sel_hi_n_*`/`sel_lo_n_*` (9 weights × 2 sides, landing on
  `adc_block`'s `REL_*`/`HI_*`/`LO_*` pins), the top-plate sampling control
  `samp_tp_n` (`TP_GN`), the input-leg control `sel_in_n` (`SEL_IN`), and the
  comparator clock `CMPCLK`.
- **Analog → digital**: the comparator decision `DOUT`/`DOUTB` (`cmp`).
- **Shared**: `VDD`, `VSS`, `VSUBS`. The analog-only `VREF`, `VCM`, `IBIAS`
  and the inputs `PINP`/`PINN` do not cross.

`sar_ctrl_a`'s port list is the rung-1 `sar_ctrl` subckt's port list verbatim
— the same 71 scalar nets in the same order — which is what lets the
behavioural model, the RTL and the gate netlist be swapped into one testbench
unedited.

### Every citation is keyed per partition, including the kind-independent items

Items 3, 4, 6, 8, 9 and 10 are kind-independent in the checklist, and a bare
`"3"` key renders one citation in **both** partitions' rows. This manifest does
not do that. It keys every citation `<item>.<partition>`, so the analog block's
DRC/LVS/Monte-Carlo evidence never stands in a digital row it says nothing
about. The cost is three honestly-uncited rows (`4.digital`, `6.digital`,
`7.digital`) where a bare key would have shown `met`. That cost is the point:
a mixed-signal claim's whole job is to say which evidence covers which
silicon.

## Provenance

repo-root-relative; no hostname, no login and no absolute path is recorded by
anything under `signoff/` (`design-evidence-tiers.md` → "Provenance hygiene in
