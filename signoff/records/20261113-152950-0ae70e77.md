## Why this record exists

Issue #772 corrects the `ciel enable` command this repository documents for a
cold-start install. `ciel`'s `-l`/`--include-libraries` **selects** the library
set rather than adding to a default, so the documented
`-l gf180mcu_fd_pr <hash>` installed only the device models — not the
`mcu7t5v0` standard cells the `sar_ctrl` sign-off chain reads, and not the two
OSU 3.3 V libraries DR-0044's `libs.ref/` listing enumerates. A reader
following the docs literally got a tree that cannot reproduce the committed
evidence. Every human-facing install command now reads
`-l default -l gf180mcu_osu_sc_gp9t3v3 -l gf180mcu_osu_sc_gp12t3v3`.

One of the corrected files is a hash-bound input of the T1 item 10 (repo
hygiene) attestation:

- `docs/environment-setup.md` — named in `signoff/repo-hygiene-inventory.json`'s
  `hygiene` list, so `klt signoff --attest 10` pins its bytes and
  `run_signoff.py --check` re-hashes them on every pull request. Editing it
  without re-attesting is exactly the drift that gate exists to catch, and it
  is what turned CI red on this branch
  (`sha256:db0e5cd8…` pinned vs `sha256:516c19f0…` committed).

The other four files this PR touches (`layout/klt_env.py`,
`sim/harness/README.md`, `sim/harness/pdk.py`,
`sim/smoke_test/run_smoke_test.sh`) are **not** inventoried by item 10 and
pin no hash here.
