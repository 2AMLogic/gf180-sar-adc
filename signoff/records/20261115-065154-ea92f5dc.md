## Why this record exists

Issue #804 fixes the four layout generators that write `klt lvs` request
documents so the invocation each `_comment` documents is derived from the path
actually written (`os.path.relpath(path, repo_root)`), corrects the 28 committed
candidate artifacts under `layout/adc-top/candidates/acq-leg-*/` that documented
the PRODUCTION request's path, and adds a mechanical guard so the class of error
cannot silently return: `sim/tools/check_lvs_request_invocations.py`, wired into
the headless CI path as `check:lvs-requests` in `package.json`'s `check:ci`
(the command list lives only there, issue #734), with its own negative-control
unit test in `sim/tests/`.

Documenting the new gate in `.github/workflows/ci.yml`'s INVENTORY comment —
the file's own contract is that each `check:ci` gate and its rationale is listed
there — made the item 10 attestation stale, because that file is named in
`signoff/repo-hygiene-inventory.json`'s `hygiene` list: `klt signoff --attest 10`
pins its bytes and `run_signoff.py --check` re-hashes them on every pull
request. Editing it without re-attesting is exactly the drift that gate exists
to catch, and it is what turned `npm run check:ci` red on this branch
(`sha256:14b3f9ae…` pinned vs `sha256:b412ff84…` committed).

The other files this change touches (`package.json`, the four generators under
`layout/adc-top/`, the 28 candidate artifacts, the new check and its test) are
**not** inventoried by item 10 and pin no hash here.

**The `README.md` hash in the envelope moved for the same designed lag the
previous record documented.** `README.md` is inventoried by item 10, but step 4
of `signoff/README.md`'s "Changing the verdict" re-points its
`signoff:current-record` citation *after* the record id exists — so every mint
records the pre-re-point bytes. The `17942b0b…` -> `f2227a70…` move above is
the previous record's (#772) re-point being picked up by this mint, and this
record's own re-point moves it again. That lag is deliberate and declared:
`README.md` is exempt from `--check`'s envelope re-hash and from
`freshness.json`'s `artifacts` pins alike, for precisely this reason.
