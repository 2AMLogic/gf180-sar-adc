# Record 20260816-050001-d002e66

- **Record ID**: 20260816-050001-d002e66
- **Claim**: README.md#target-specification -- Offset error <= 2 LSB untrimmed (3-sigma mismatch). This record measures the dominant term of the comparator's input-referred offset; spec/comparator-budget-memo.md S3 combines it with the latch's own term -- DERIVED from the same measured A_Vt and the measured preamp gain, because a reset-and-regenerate latch has no DC operating point to sweep -- and compares the total against the 2 LSB bound.

- **Statistical convention**: N/A (corner-matrix claim, not a distribution claim)
  - **Seed handling**: ngspice `setseed 20260801` at the top of the control block, then 150 draws per PVT point via `reset` inside a dowhile loop (each reset re-evaluates the agauss expressions in the fets_mm subckts). The SAME seed is used at every PVT point -- common random numbers -- so movement of the reported sigma across the grid is a real PVT effect and not sampling noise; N for statistical-error purposes is 150, not 150 x 45. Seeding mechanism per sim/device-mismatch-mc/: `setseed <n>` is the only ngspice control that works here (`set rndseed` is silently ignored and `.options seed` freezes the draw).
  - **Scope**: mismatch-only
  - **Sigma level**: 1-sigma of the input-referred offset is reported directly, alongside the 3-sigma value the ratified <= 2 LSB offset row is stated at. Statistical precision on each sigma is 1/sqrt(2N) = 5.8 % at N = 150. N is 150 rather than device-mismatch-mc's 300 because this deck's per-draw cost is a six-point DC sweep of a full preamp rather than a single diode-connected pair, and 45 PVT points x 300 draws does not fit the verification budget DR-0007 states; the resulting 5.8 % precision is still far finer than any margin the offset budget leans on.
- **Note**: TWO OPERATING POINTS PER DRAW, ONE INSTANCE. Gain is measured by `alter`-ing the shared differential source from 0 to +2 mV and re-running op on the SAME instance. Using two separate instances (as the deterministic deck next door does) would be wrong here: their mismatch draws are independent, so their difference would contain the offset difference rather than just the gain. av_sigma_pct is the check that this worked.
- **Note**: WHAT IS NOT IN THIS RECORD. (a) The StrongARM latch's own offset. It has no DC operating point, so this deck's method cannot reach it at all; referred to the comparator input it is divided by the gain measured here, and spec/comparator-budget-memo.md S3.3 derives it from the same measured A_Vt rather than measuring it. sim/comparator-regeneration/'s two-way polarity check at half an LSB is the null control that bounds any SYSTEMATIC (non-mismatch) latch offset below that level. (b) Load-resistor mismatch, which this PDK does not model at all (see the sig_rpair_uv null control). (c) Current-factor (beta) mismatch is INCLUDED here -- unlike sim/device-mismatch-mc/, which biases in deep subthreshold specifically to suppress it -- because the preamp runs its pair in moderate inversion. The prediction that this would make avt_back_mv_um read visibly ABOVE the 7.208 mV*um threshold-only coefficient WAS NOT BORNE OUT: record 20260801-035221-90d7e67 measured 6.97 mV*um, 3.2 % BELOW the standalone extraction and well inside the combined statistical error of the two (5.8 % here at N = 150, 4.1 % there). The beta-mismatch term is therefore not resolvable at this bias -- consistent with devchar S5.3, which states that beta mismatch is not characterized in this PDK -- and the offset budget rests on threshold mismatch alone. Do not read the avt_back_mv_um bounds below as a test of that prediction; they are a sanity envelope (see their own description).
- **Note**: sw_stat_mismatch is set in the NETLIST FRAGMENT, not in the manifest params: the harness emits manifest params ahead of the model includes and design.ngspice sets sw_stat_mismatch = 0, so a manifest param would be silently overridden and the whole Monte Carlo would collapse to sigma = 0.
