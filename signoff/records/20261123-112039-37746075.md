# T1 signoff re-attestation after the guard-capacitor generator change

**Record id:** `20261123-112039-37746075`

**Issue:** #981

**Supersedes:** [`20261123-053735-4e9779b4`](20261123-053735-4e9779b4.md)

Issue #981 changes `design/sar-logic/gen_sar_logic.py` so the SAR guard
capacitor is computed from the documented settle delay instead of being a
literal. That file is attested by the item 1 digital design-source envelope,
so the envelope had to be re-minted. This record is that re-attestation and
nothing else.

The graded report is **byte-identical** to the one it supersedes: no row moved.
The block remains at `tier: none`, with **19 of 22 T1 rows met** and one
recorded as `not_applicable`. See the [graded report](../reports/20261123-112039-37746075/signoff.json)
and its [text rendering](../reports/20261123-112039-37746075/signoff.txt).

What changed on disk:

- `design/sar-logic/gen_sar_logic.py` hash
  `sha256:adad37cb…` -> `sha256:22568418…`, re-attested in
  [`design-source.digital.json`](../design-source/design-source.digital.json)
  and mirrored in `freshness.json`.
- The emitted SPICE is unchanged. `gen_sar_logic.py --check` reports all
  generated netlists up to date, and the default guard capacitor still formats
  to the committed `721.348f`. Only the generator source hash moved.

The grading command was `python3 -I signoff/run_signoff.py --regen --klt <pinned klt>`
with `klt 0.7.1.dev1744+g44cc42323184`, installed from the commit pinned in
`signoff/toolchain.json` into a throwaway venv, and `klayout 0.30.14` (the
package that build resolved; the previous record used `klayout 0.30.10`). The
item 1 digital envelope was first re-minted with
`klt signoff --attest 1 --inventory signoff/design-source/inventory.digital.json`
under the same pinned build.
Run `python3 -I signoff/run_signoff.py --check` to verify the committed report,
citations and current-record pointers.
