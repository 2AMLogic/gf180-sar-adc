## What this record does NOT assert

- **That any bench succeeds.** Item 9's inventory attests presence, sha256 and
  pins. The only command it runs is the cold start: `python3 -m unittest
  discover -s sim/tests -t sim/tests` (analog) and `python3
  design/sar-logic/gen_sar_logic.py --check` (digital). Both are PDK-free. The
  ngspice benches need ngspice >= 46 and the open_pdks-pinned gf180mcu models
  (`sim/toolchain.json`) and are listed with that reason, not run. A reviewer
  confirms the documented cold-start commands are the ones in `README.md` /
  `sim/README.md` (the issue's out-of-band criterion).
- **That `make check` cold-starts.** It exits 1 on the machine that minted this
  record (the installed ngspice/PDK drifted from `sim/toolchain.json`), so it
  is not the attested command.
- **That CI is green.** Item 10's four checks (the `test_harness.py` unit
  tests, compileall, markdown links, characterization-summary citations) are
  commands the CI workflow also runs; a green run is read off the pull
  request. `run_signoff.py --check`, the README status-table check and the
  rest of the unit-test suite are excluded: they read the committed verdict,
  so attesting them would be circular. `README.md` and `signoff/README.md`
  are not hash-pinned by `--check` for the same reason (every `--regen`
  re-points their record pointer), though `README.md` is inventoried.
- **Complete coverage of every measurement.** Benches are the tracked
  `sim/<family>/testbench*/` files (minus fixtures), per-family runner and
  analysis scripts, and the shared runners. No completeness audit like the
  `sg13g2-lna` reference's `testbench-coverage.json` exists here.
- **Any change to a ratified spec row, a measurement, or a historical record.**
