## Reproduce

```bash
pip install 'klayout-tools @ git+https://github.com/2AMLogic/klayout-tools@c622e8addb362491664d44ba4d717f354ca88bbd'
pip install 'klayout==0.30.10'
python3 layout/power/run_power.py --check    # re-run and assert
python3 layout/power/run_power.py --verify   # re-read this record, no klt
```

The JSON report is the stable contract; the `.txt` capture beside it is a courtesy view, not the source of truth. Each committed JSON carries two added keys that are **this runner's** record, not part of `klt power`'s own envelope: `_klt_exit_code` (the process exit status, which `--verify` strips before asserting) and `_layout_sha256`. The second exists because `klt power` emits no `provenance` block at all — unlike `klt erc`, whose `provenance.input.content_hash` is the tool's own attestation of the bytes it read (klayout-tools#1968/#2036). Filed upstream as klayout-tools#2349; until it lands, this digest proves only that the committed report has not been separated from the geometry it was minted against. The composed spec committed beside each report is the exact file `klt power` was handed, and `--verify` re-composes it from `adc_block.power-spec.json` + `cases.json` and compares it byte for byte.
