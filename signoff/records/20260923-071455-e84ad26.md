## Why this record exists

**The layout changed.** Issue #356 drew an `Nplus`-marked, contacted n+ tap
inside every one of `ADC_BLOCK`'s 25 `Nwell` islands and routed each to
`vdd`; closed both substrate-tie guard rings' `Metal1` at the corners,
marked them `Pplus`, labelled them `vss` and strapped them into the block's
own `vss` island; and redrew every tap contact as a `CO.1`-compliant array
of 0.22 µm squares. The decision is
[DR-0035](../../spec/decision-records/DR-0035-well-taps-and-tie-straps.md),
which supersedes DR-0032 by that record's own first revisit trigger.

`ae4e8964…`, and every citation resting on those bytes had to be re-minted

## Why item 11 is `met`, stated so it can be argued with

`klt signoff`'s `_grade_power_delivery` graded this row `unmet` /
`supply_spec_incomplete` for as long as `layout/erc/adc_block.supply-spec.json`
declared no `ties[]`. That was the correct verdict on the old geometry and
this repo's records say why at each stage: #330 left the tie half
*uncomputed* (a declaration the implant-free stream could not express), #340
measured the same question directly and found it *failed on evidence* (25
untapped wells, two unstrapped rings), and DR-0032 recorded that drawing
implants without taps to mark would change no number in any report.

What makes the row `met` now is not a relaxed declaration. It is that the
declaration became **true and checkable in the same change**:

- The spec declares `ties[]` — `tap_layer: "22/0"` narrowed by
  `tap_requires: ["32/0"]`, `connect_to: "Metal1"`, `net: "vdd"`. `Nplus`
  32/0 is drawn on the 25 tap strips and nowhere else, so the derived tap
  region is exactly those strips.
- The committed run reports `erc_status: "clean"`,
  `erc_finding_count: 0` — zero `erc.unconnected_net`, zero
  `erc.supply_short`, zero `erc.missing_tie`.
- **The tie rule ran.** `erc_coverage.checked` carries
  `erc.missing_tie:["nwell_tap"]`, and `layout/erc/cases.json` asserts that
  entry by name. A zero from a skipped rule and a zero from a rule that ran
  are the same number in `erc_finding_counts`; this repo now refuses to
  conflate them.
- **The zero could have been non-zero.**
  `layout/erc/controls/adc_block.tie-wrong-implant.control.json` is the same
  declaration narrowed on `Pplus` 31/0 — an implant this stream really
  draws, but only on the guard rings, which sit outside every well — and it
  reports all 25 wells untapped. It replaces the old `tie-narrowed` known
  gap, whose 25 findings came from an *empty* tap region and so
  discriminated nothing.
- An **independent** instrument agrees. `layout/erc/well_tap_audit.py`,
  unchanged since #340, re-derives the answer from the drawn layers with no
  extraction deck and no net model: 25 well-tap candidates in 25 wells,
  both implants present, one closed `Metal1` annulus per ring carrying a
  `vss` label, ring contacts at an exact 0.22 × 0.22 µm.

### What `met` on this row does NOT claim

Stated here because a `met` row is exactly where an unstated limit does
damage:

- **The substrate tie is not graded by `erc.missing_tie`.** `klt erc`'s tie
  declaration requires a drawn `well_layer`, and the p-substrate of a bulk
  process is not drawn, so the check can only ever grade n-well taps here.
  (Filed generically from this repo as klayout-tools#2255 and **closed
  upstream** by klayout-tools PR #2273's asserted `well_boxes` — which
  merged *after* `layout/erc/toolchain.json`'s pinned commit, so it is not
  available to this run.) The two `Pplus` rings are covered by their
  membership of the one `vss` island (which zero `erc.unconnected_net` on
  `vss` does assert) and by the geometric audit — not by this rule.
- **`pdn: no`, `power_connectivity: unchecked`.** No `klt place-and-route`
  response is cited, because this analog partition has none; item 11's
  compound condition does not require one of an analog block, and the
  rendered row says so.
- **`T1#11.digital` is still `unmet` / `no_evidence`**, unchanged and
  deliberately uncited: no LVS of the routed `sar_ctrl` macro exists in this
  repo, and citing the analog block's LVS there would claim coverage that
  partition does not have.
- **Item 11 says the supply is *connected*, not that it is *adequate*.** The
  IR/EM read re-run alongside this one
  (`layout/power/records/20260923-070149-e84ad26.md`) still reports the
  landed-at-`ADC_DECODE_BANK_P` case missing DR-0034's 33 mV budget
  (33.552 mV, up from 33.029 mV). Nothing about a `met` item 11 changes
  that, and #378/#379 remain open.

## What did not change, and was checked rather than assumed

- **No citation, envelope, artifact hash, or row status was hand-edited to
  make `--check` pass.** The manifest was re-pointed at the re-minted
  reports, `--regen` re-derived every hash in `signoff/freshness.json` from
  those files, and `--check` was run afterwards. The hand-written `note` /
  `report_citation_note` prose in `freshness.json` was updated for item 11
  and item 7 because it had become false, not to change any assertion.
- **`--selftest` still catches all ten tampered inputs**, including the
  compound-citation case (`11.analog part 0 (erc)`: `content_hash` tampered
  in the manifest, `freshness.json` left as committed).
- **Item 7's `artifacts` pin moved** (`layout/adc-top/comparator.gds`), and
  its row did not: it still renders `unmet` / `check_failed`. That pin
  tracks the comparator GDS *as committed today* precisely so the gap
  against the errored 2026-08-15 `klt pex` run's own
  `provenance.input.content_hash` stays visible. #356 widened that gap; the
  citation's note now says so.
- **One flow was deliberately NOT re-run, and nothing here cites it**: the
  parasitic-extraction flow and the five extracted campaigns built on it
  (`layout/adc-top/parasitics/`) still describe the pre-#356 geometry. No
  T1 row in this verdict rests on them — item 7's `klt pex` citation is
  comparator-scoped and already `unmet` — but the staleness is real, is
  disclosed at the top of that directory's README, and is tracked as
  **#383**.
