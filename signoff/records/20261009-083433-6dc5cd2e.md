## Why this record exists

PR #462's review found a loophole in `sim/tools/check_characterization_summary.py`.
The superseded record says a newer same-campaign, same-mode record is exempt
from needing an exception when it is "linked in the row". The checker counted
any same-row link, whatever its role. A newer record added to a row as
`historical`, beside an older `governing` citation with no `Supersedes` edge,
therefore passed silently, which is the inverted classification the check
exists to catch.

The checker now counts only a same-row citation marked `governing` or `current`
(that record is then freshness-checked itself). A newer record linked as
`historical` needs an exact, reasoned exception like any other. A regression
test covers both the failing case and the excepted case. On the committed
summary the result is unchanged: 64 citations classified, the same 28
exceptions, none added or removed.

The sync-section paragraph of `sim/characterization-summary.md` described the
old rule and was corrected. That file is the hash-pinned source of both item-8
envelopes, so the pin moved:

```
sha256:0e834650...5074d  ->  sha256:b89afb0e...37e1f  (full: sha256:b89afb0ec4c497014aecb11513c85521a73e3ca9e66322da63d3692853637e1f)
```

Both envelopes gained an eighth `partial_updates[]` entry. As before,
`reread_commit` and `reread_date` are not bumped: this is not a row-by-row
re-read.
