## What moved, and why it is `unmet` rather than `met` — read this before the row above

**Nothing on this block's silicon changed.** What changed is that the
manifest can now *cite* the evidence #330 landed, and the grader can now
*read* it. Both were blocked by the same gap, and both are closed here.

### The gap: item 11 is the one compound T1 item

Every other T1 item's manifest entry is one file. Item 11 is not
(klayout-tools#2025, `_grade_power_delivery`): its evidence is a **set**,
and `klt signoff` accepts that set as a JSON array of ordinary evidence
entries. For an analog (or full-custom digital) partition the set must
contain:

- a **`klt erc`** citation — a supply-spec run naming at least one
  `"kind": "supply"` net and at least one `ties[]` declaration, neither
  reported degenerate by the run itself, with every declared supply
  resolving to exactly one electrical island;
- an **`lvs`** citation — "the same report item 4 grades", i.e. the LVS
  compare whose reference actually carried the supply nets.

`signoff/run_signoff.py`'s `manifest_citations()` understood only the two
single-artifact shapes this repo had needed through #339 — a bare path
string, or `{"file": ..., "content_hash": ...}` — and raised on anything
else. A list-valued `"11.analog"` entry was therefore not a citation this
script could grade at all; the row rendered `no_evidence` with the evidence
sitting, committed, in `layout/erc/`.

### The fix, and what it touches

`manifest_citations()` now returns a `list` of `(file, content_hash)` pairs
for a list-valued manifest entry (`_manifest_citation_part()` normalizes
each element through the exact same rule a single citation goes through),
and every downstream consumer branches on that shape:

- **`check()` step 1** (manifest ↔ freshness agreement) and **steps 2-3**
  (envelope fields, artifact hashes) now run per-part for a compound
  citation, via two new shared helpers
  (`_check_citation_agreement`/`_check_envelope_and_artifacts`) so the
  compound path can never drift from the single-artifact path it was split
  out of.
- **Step 4b** (report ↔ manifest row-by-row agreement) now compares a
  compound row's `citation["parts"]` against the manifest's list,
  positionally — `_grade_power_delivery`'s own citation shape leads with the
  first part and carries every part under `parts`, in `(erc, lvs,
  place-and-route)` order, which is the order this manifest's list follows.
  In practice this branch is not exercised by the row committed here: item
  11's own grader only ever builds a `citation` on the `met` path (see
  below), so `T1#11.analog` renders `citation: null` exactly as `T1#7.analog`
  does, and both are declared uncomparable via a new
  `report_citation_note` in `signoff/freshness.json` rather than silently
  skipped.
- **`signoff/freshness.json`** gained an `"11.analog"` citation carrying a
  `"parts"` list (one entry per cited artifact, each with its own `role`,
  `envelope_asserts` and `artifacts`) instead of the flat shape every other
  citation uses. The `_comment` documents the new key.
- **`--regen`**'s freshness-rewrite loop and **`--selftest`**'s overlay
  builder (`_overlay()`) both gained the same branch, so a compound
  citation's parts are copied into the negative-control sandbox and
  re-hashed on every `--regen` exactly like a single-artifact citation's
  are.
- **`--selftest`** gained a compound-shape-specific tamper case (acceptance
  criterion): it corrupts one part's `content_hash` **in the manifest**
  while leaving `signoff/freshness.json`'s own declared pin untouched, which
  only the new per-part comparison in `check()`'s step 1 can catch. Ten
  tampered inputs now, all caught (was nine, through #339).

### Why `11.analog` still reads `unmet` — `supply_spec_incomplete`, not `met`

Citing the evidence does not make it pass. `_grade_power_delivery` requires
the cited `klt erc` run's supply spec to declare **at least one `ties[]`
entry**, none of them reported degenerate. The committed
`layout/erc/adc_block.supply-spec.json` declares **none** — `ties[]` is
absent entirely — so the grader renders `supply_spec_incomplete` before it
even reaches the question of whether any declared tie is clean.

That omission is not an oversight this pass could fix by editing the spec.
`ADC_BLOCK` draws no implant layers (`Pplus` 31/0, `Nplus` 32/0 carry zero
shapes in the committed GDS), so the real gf180mcu tap boolean
(`COMP ∩ Nplus`) has nothing to intersect — there is no declarable `ties[]`
entry that would mean anything. `spec/decision-records/DR-0032-implant-layers-not-drawn.md`
(landed the same day as this pass, #359) settles the question a `ties[]`
declaration would have asked, from geometry instead:
`layout/erc/well_tap_audit.py` finds every `COMP` polygon touching any of
this block's 25 `Nwell` islands is also transistor source/drain/channel —
**zero** n-well taps drawn anywhere in the block — and that its two
substrate-tie guard rings are contacted but strapped to nothing (no
`Metal1_Label`, no route, and the `Metal1` ring itself is open at all four
corners). Declaring a bare `tap_layer: "22/0"` instead — the other
alternative — would not help either: klayout-tools#2199 classifies such a
declaration *degenerate* for exactly the same underlying reason, and the
committed `layout/erc/controls/adc_block.tie-bare.known-gap.json` control
reproduces that skip on every re-run.

**Read `unmet`/`supply_spec_incomplete` as "we looked, here is the
artifact, here is the one condition it cannot meet and why" — strictly
better than `no_evidence`'s "nobody has looked".** The tie half of item 11
is *failed on evidence*, per DR-0032, not uncomputed for want of a
declarable layer. The layout work that would change this answer — drawing
25 n-well taps strapped to `vdd` and strapping both substrate-tie rings to
`vss` — is tracked separately (#340) and is deliberately out of scope here:
this pass is grading-wiring, split out of #330 to keep that change scoped to
the ERC flow itself (per this issue's own "Split out of" note).
