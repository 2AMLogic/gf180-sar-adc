## 2. Mismatch estimate for a trimmed edge (analytical, with provenance)

**Why not Monte Carlo.** The PDK has no local capacitor mismatch model
(`layout/floorplan-matching-plan.md` Sec 1.3; `sim/device-characterization-report.md`
Sec 5.1), so an ngspice MC would report zero edge effect whatever the trim.

**Model.** An edge bias `eps` (fractional change of a unit cap per cardinal side
with no neighbouring tile) is added to the real units on trimmed edges, using
the generator's own `centroid_tiling` assignment, and evaluated through the same
transfer function as `sim/mc-cdac-mismatch/testbench/mc_cdac_mismatch.py`
(end-point INL, DNL over 511 transitions; gain error as the sum over both
sides' 1024 units, Sec 3.6 of `spec/cdac-sizing-memo.md`). The response is linear in
`eps`, so results are LSB per 1 % of `eps`. **`eps` is not known for this PDK**;
the output is a tolerance, not a prediction.

**Margin left by random mismatch** (3σ, `sigma_u` = 0.5000 %, committed
`sim/mc-cdac-mismatch/yield-evidence-656/klt-yield-report.txt`, N = 20000;
gain: 32 · `sigma_u` per memo Sec 3.6), added linearly (conservative):

| Row | Limit | 3σ random | Room for a systematic term |
|---|---|---|---|
| DNL (stretch) | 0.5 LSB | 0.392 | 0.108 LSB |
| INL (stretch) | 0.5 LSB | 0.276 | 0.224 LSB |
| Gain error | 0.5 LSB | 0.480 | **0.020 LSB** |

| Option | bbox µm | Area saved (both sides) | max DNL / INL / gain per 1 % `eps` (LSB) | Break-even `eps` (DNL / INL / gain) |
|---|---|---|---|---|
| keep ring | 216.4 x 114.0 | 0 | 0 / 0 / 0 | — |
| trim L+R | 203.6 x 114.0 | 2,918 µm² | 0.040 / 0.020 / 0.64 | 2.7 % / 11.2 % / **0.031 %** |
| trim B+T | 216.4 x 101.2 | 5,540 µm² | 0.320 / 0.242 / 1.28 | 0.34 % / 0.93 % / **0.016 %** |
| trim all four | 203.6 x 101.2 | 8,131 µm² | 0.320 / 0.244 / 1.92 | 0.34 % / 0.92 % / **0.010 %** |

Full trim recovers 8,131 µm², slightly more than the issue's -7.4k target,
because the issue's baseline is the nominal 204.8 x 102.4 grid.

**Corners.** The estimate is corner-independent by construction: it is a
geometric, ratiometric effect on one cap array, and the PDK's only capacitor
statistics (`sw_stat_global`) cancel in a capacitor ratio. No PVT sweep was
run, and none would change the number. Whether `eps` itself moves with
temperature is not modelled (no PDK data).

## 3. Recommendation: **keep the ring**

- The gain-error row has 0.020 LSB of room after random mismatch, so any trim
  tolerates only `eps` ≈ 0.01-0.03 % per exposed side. Etch-loading edge biases
  on a 4 µm plate are typically far larger than that (a 10 nm sidewall shift is
  ~0.25 % per side; an **unverified illustrative figure, not PDK data**), and
  this repo cannot measure it. Trimming would spend a margin that is already
  gone on a bias nobody can bound.
- The gain-error caveat: if gain error is judged ratiometric to the array's own
  sampled charge, a uniform edge bias partly cancels and the binding rows become
  DNL/INL (break-even 0.34 % for the B+T edges). That reading is not what the
  memo's Sec 3.6 states, and this record does not adopt it.
- **L+R only** is the least risky partial trim (DNL 2.7 %, INL 11 % break-even,
  2,918 µm² for both sides) but it still fails gain at 0.031 %. If anyone wants
  it, it needs a spec/decision-record route (`spec/`) and foundry or test-chip
  edge-bias data first; it is not recommended here.
- The unmeasurable-`eps` gap is the thing that would change this: foundry MiM
  edge data, or a mismatch-capable extraction path (#17).
- Out of scope and not done: any layout change. Trimming the bottom edge would
  also move `SPINE_EXIT_Y` and the block-level routing.
