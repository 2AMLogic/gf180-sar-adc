# LVS record 20261115-021029-784b4d3b

Append-only adjudication record for the `device.geometry_not_compared` delta that
makes `layout/lvs/run_lvs.py --check` fail under the `klt` release #652 targets.
Not minted by the runner: every number below was re-measured for this record, in
throwaway environments, against the same committed geometry the runner asserts
on. A re-run mints its own record; this one is never edited in place.

- **Record ID** — `20261115-021029-784b4d3b`
- **Claim** — the `device.geometry_not_compared` failures `--check` reports under
  `klt` 0.8.0 are **disclosure, not difference**: the newer `klt` reports a
  device-geometry parameter comparison the pinned build silently skipped. The
  LVS verdict is unchanged (`status: match` for every case, both builds), the
  same devices exist on both sides, and no netlist or layout change is involved.
  It is an intentional, documented upstream diagnostic (klayout-tools#2461),
  not a tool defect and not a design discrepancy -- nothing to file.
- **Why that is the right branch of the AC** — three ways to be a delta, and the
  evidence excludes two of them. (a) *Compares less*: excluded -- KLayout's
  `NetlistComparer` primary-only behaviour is unchanged between the builds; 0.6.0
  compared `C`/`R` exactly as 0.8.0 does. (b) *A real netlist/layout
  difference*: excluded -- each entry reports identical device counts on both
  sides (1024/1024 capacitors, 2/2 resistors), the primary-parameter compare
  passed, and the committed netlists still match their references under the
  pinned build on this host. (c) *Reports a silently-skipped comparison*: what
  the entries themselves say -- `['A','P']` (capacitor) and `['A','L','P','W']`
  (resistor) "took no part in this compare and each is NOT verified".
- **Geometry provenance** — the committed block layout `layout/adc-top/`
  (unchanged since the 20261101 records; sha256 below), the committed
  references under `layout/adc-top/cells/` and `layout/adc-top/`, and the
  manifest `layout/lvs/cells/cells.json`. No geometry was regenerated.
- **Overall** — ADJUDICATED (delta explained; no re-baseline performed here --
  re-minting the manifest expectations is #652's job, which this unblocks)

### The devices involved (verbatim, from `klt lvs --format json` under 0.8.0)

One `severity: "warning"` entry per participating non-MOS device class per run,
identical on `side: "both"`:

- `adc_top` (1): class **`cap_mim_2f0_m4m5_noshield`** (capacitor),
  `layout_devices: 1024, reference_devices: 1024`, compared `['C']`,
  not_compared `['A', 'P']` (reason `secondary`).
- `adc_block` (2): the same capacitor entry, plus class **`PPOLYF_U_1K`**
  (resistor), `layout_devices: 2, reference_devices: 2`, compared `['R']`,
  not_compared `['A', 'L', 'P', 'W']` (reason `secondary`).

Entry text (capacitor; the resistor's is the same shape): "device class
'cap_mim_2f0_m4m5_noshield' is a capacitor class, whose ['A', 'P'] parameter(s)
KLayout declares *secondary*: kdb.NetlistComparer compares primary parameters
only, so none of them took part in this compare and each is NOT verified -- […]
Name them in options.compare_parameters to compare them (see docs/cli/lvs.md,
'device.geometry_not_compared')".

### Upstream provenance

The category is upstream issue **klayout-tools#2461** ("closes the last silent
gap"): KLayout marks only `R` primary on `DeviceClassResistor` and only `C` on
`DeviceClassCapacitor`, so such a class's entire geometry sits outside every
default compare -- in **both** builds; only the disclosure is new. Confirmed in
the installed sources: `CATEGORY_DEVICE_GEOMETRY_NOT_COMPARED` and
`_GEOMETRY_DISCLOSURE_CLASS_KINDS` exist in 0.8.0's `lvs.py`
(`grep -rn geometry_not_compared` over the installed package: 0.8.0 -- 7
source hits; 0.6.0 -- 0). The entries
are gradeable through the report's `device_parameter_coverage` block, built
from the same determination; `options.compare_parameters` is the escape hatch
if a future record wants `A`/`P` (or `L`/`W`) actually compared.

## Other 0.8.0 deltas observed in the same run (context for #652, not adjudicated here)

The same `--check` run fails on three further deltas beyond this issue's two.
They belong to #652's re-baseline, recorded here so that re-baseline sees the
whole picture and not just the two deltas this issue was filed on:

1. **Deck class-list expansion** (`lvs_unit` extract row): the 0.8.0 gf180mcu
   deck declares 19 device classes where `cells.json` pins 7 -- 12 new
   `cap_nmos_*` / `cap_pmos_*` classes (MOS-capactor recognition).
2. **New extract warning on cap-bearing cells** (`adc_cdac_cell`, `adc_top`,
   `adc_block`, +1 warning each): "N drawn capacitors […] written as a
   fixed-value 'C' card (the deck's nominal area+perimeter value) -- PDK
   process corners […] do not apply to it; pass --pdk to bind the PDK capacitor
   subcircuit".
3. **Netlist byte drift on `comparator` and `adc_block`**: exactly 2 device
   cards each, the poly resistors, change written form --
   `R$1348 vdd XCMP_pop vss 150000 ppolyf_u_1k L=150U W=1U` becomes
   `X$1348 vdd XCMP_pop vss ppolyf_u_1k r=150000 L=150U W=1U` -- same devices,
   same value, same L/W; a netlist-writing format change, not a connectivity
   change. (Not the `$NNN` renumbering of toolchain.json's PR #195 caveat:
   these lines are the only diff.)
