## Why a third record on the same day

Nothing about this block moved. **Two manifest edits raced, each graded
against a manifest that did not yet carry the other.**

- `20260921-175049-93ddfe3` (#338, this branch) re-pointed `4.analog` at an
  LVS report with a real `provenance.input.content_hash`. It graded a
  manifest whose item 8 was still uncited.
- `20260921-175516-93ddfe3` (#339, merged to `main` as PR #361 while this
  branch was in review) added the two item-8 generic evidence envelopes. It
  graded a manifest whose `4.analog` was still the bare, unpinned string
  citation.

Rebasing this branch onto `main` merges both manifest edits, and at that
point **neither committed report describes the manifest any more**:
`run_signoff.py --check`'s step 4b (the "was the report graded on the
citations the manifest names NOW" gate) fails on `T1#4.analog`, exactly as
designed. That gate is the reason this record exists — it refused to let a
merged manifest stand on a verdict minted before the merge.

The fix is the one `signoff/README.md` § "Changing the verdict" prescribes
and the only one it allows: re-run `--regen` against the merged manifest and
write a record. **No citation, envelope, artifact hash, or row status was
hand-edited to make `--check` pass.**
