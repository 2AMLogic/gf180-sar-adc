## Why this record exists

**The document behind T1 item 8 changed again, this time to withdraw a wrong
number.** `sim/characterization-summary.md`'s `V_CM` row quoted the #358
full-PVT campaign's power result as *"worst `p_total` 207.884 → 223.961 µW,
margin 4.81× → 4.47×"*. That figure was wrong, and wrong in its **direction**,
not merely its magnitude.

`sim/vcm-drive-impedance/gen_vcm_variant.py` substitutes a 0 V ammeter for the
ideal V_cm source on the one deck whose manifest measures `i(vcms)`
(`sim/adc-power/`), so the measured vector survives the substitution. It
emitted that ammeter as `vcms vcmi vcmd dc 0` — positive terminal on the
**source** side — the reverse of the line it substitutes for
(`vcms vcmn 0 dc {vcm}`, positive terminal on the **island** node `vcmn`).
ngspice reports `i(vsrc)` as the current *into* the positive terminal, so the
reversal reversed `i(vcms)`; `sim/adc-power/testbench/tb.json` derives
`p_vcm = -ivcm*(vddm/2)*1e6` and folds the same `ivcm` term into `p_total`
inside the same negation, so **every `p_total_*` in the V_cm-network arm — and
in only that arm — was off by `2 × p_vcm`**.

Nothing caught it for a fortnight: `p_vcm_*` carries no bound, so all 27 points
scored PASS against a manifest check that never saw the term. It surfaced only
by comparing the two arms' `p_vcm` columns against each other.

`signoff/run_signoff.py --check` re-hashes the wrapped document on every pull
request and fails loudly on any edit to it, which is why this is a re-mint and
not an edit.

  `sim/adc-power/testbench/tb.json`, and every `p_total_*` stayed an order of
  magnitude inside the 1 mW check under both signs, so all 27 points of the
  affected arm read PASS either way. The defect was a wrong number in a

  `sim/adc-power/records/20260923-114021-836a876.md` and its netlist snapshot
