## The half that stays routed, not taken: SB.10

#838's measurement — that `poly2.enclosing.sab.1` (an enclosure rule)
forces an unmarked Poly2 band around the marked resistor body, which
merges both terminal leads into one contact region and makes both
resistors vanish from the extracted netlist (27 devices instead of 29)
— carries forward unchanged. Its two checkable premises were
re-verified live in this tree rather than quoted:

1. **Same deck bytes.** The 0.8.0 deck this pass ran has content hash
   `sha256:0eb6df1b…7e48666`, identical to the build #840 measured (and
   to PR #851's). The deck source at this pin still derives the
   resistor's terminal ("C") region as "`Poly2` minus the recognised
   body" with the recognised body still
   `poly2.and(sab).and(res_mk).and(resistor)` — both lines re-read in
   the installed deck file.
2. **Same extraction outcome.** The rebuilt streams extract exactly as
   before: both resistors still `150000 ppolyf_u_1k L=150U W=1U`,
   `device_counts` still `{nfet 15, pfet 12, ppolyf_u_1k 2}` at flat
   level, and the only netlist bytes that moved are the two resistor
   instance-comment centroid lines (+0.15 um, the gap delta) — re-proven
   by the green `run_lvs.py --regen`/`--regen-manifest`/`--check`
   sequence minting
   [`layout/lvs/records/20261119-084658-939fe789.md`](../../layout/lvs/records/20261119-084658-939fe789.md)
   in this tree.

The halo counterfactual itself was not re-drawn: the argument it
demonstrates is geometry-independent (one unmarked band touching the
whole perimeter merges both leads regardless of the column gap), and
the counterfactual's own geometry (the SB.10-forced 680 nm minimum) is
unreachable from this rebuild's scope. The full drawn-and-measured
table remains PR #851's
`layout/drc/records/20261116-062800-f2180c30.md`; this record carries
it forward on the re-verified premises above, per issue #890's
"re-checked, carried forward" reading of the SB.10 half.
