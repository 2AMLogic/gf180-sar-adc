## Why this record exists

**The layout changed.** Issue #378 moved `ADC_BLOCK`'s three block-level
`vdd`/`vss` straps from Poly2 risers to **Metal2**, landing on each
sub-block's Metal1 trunk through a single Via1. The decision is
[DR-0037](../../spec/decision-records/DR-0037-block-level-supply-straps-on-metal2.md).
`vcm` was deliberately left on Poly2, and every in-sub-block terminal riser
is untouched.

`layout/adc-top/adc_block.gds` therefore moved from sha256 `ae4e8964…` to
`501f3985…` (and `adc_top.gds` from `0e857b8e…` to `f5bce13a…`), and every
citation resting on those bytes had to be re-minted under its own pinned
build before this verdict could be re-graded. All four were, in this order:

| Flow | New record | Result |
|---|---|---|
| DRC (`klt 0.5.0+gb15edf5e3a2e`) | `layout/drc/records/20260923-084515-5f13cf9.md` | PASS — `adc_top` and `adc_block` clean |
| LVS (`klt 0.5.0+gb15edf5e3a2e`) | `layout/lvs/records/20260923-084536-5f13cf9.md` | PASS — both `match`, 0 mismatches |
| ERC (`klt 0.5.0+g67d617f899c7`) | `layout/erc/records/20260923-084733-5f13cf9.md` | PASS — all five cases |
| IR/EM (`klt 0.6.0`) | `layout/power/records/20260923-084734-5f13cf9.md` | PASS — two FAIL verdicts became PASS |

## What moved in the verdict

```
block: gf180-sar-adc  kind: mixed-signal
tier: none
T1: 7/22 items met        (unchanged)
```

**No row changed.** Every entry in `items[]` is identical to the superseded
record, field for field: same statuses, same reasons, same `tier: null`.
Checked mechanically, not by reading:

```python
rows = lambda d: {(i["id"], i.get("partition", "")): (i["status"], i["reason"])
                  for i in d["items"]}
rows(old) == rows(new)        # True
old["t1_met_count"], new["t1_met_count"]   # (7, 7)
old["tier"], new["tier"]                   # (None, None)
```

That is the intended outcome and it is worth stating as a claim rather than
an absence. The T1 rows this change touches are **structural** — item 3
(DRC clean), item 4 (LVS clean), item 11 (power delivery, structural: one
electrical island per supply, with a computed tie verdict). A strap that
changes which *layer* carries a net, without changing which nodes are
connected, must leave all three exactly where they were. If any of them had
moved, the change would have done something other than what DR-0037 says it
did.

## What did not change, and was checked rather than assumed

- **No citation, envelope, artifact hash, or row status was hand-edited to
  make `--check` pass.** The manifest was re-pointed at the re-minted DRC /
  LVS / ERC reports and its two GDS-derived `content_hash` pins updated to
  the bytes the tools themselves attest
  (`provenance.input.content_hash`); `--regen` then re-derived every hash in
  `signoff/freshness.json` from those files, and `--check` was run
  afterwards.
- **The LVS citation's `content_hash` did not move at all**
  (`sha256:4dbc3f3a…`), because it pins the *netlist*, and the extracted
  netlists are byte-identical before and after. That is an independent
  confirmation of DR-0037's core claim: this change moves conductors, not
  connectivity.
- **`--selftest` still catches every tampered input**, the compound
  citation included.
- **The item 11 freshness note was rewritten** because it described the
  re-mint as #356's; it is #378's now. Prose, not an assertion.
- **One flow was deliberately NOT re-run, and nothing here cites it**:
  `layout/adc-top/parasitics/` and the five extracted campaigns built on it
  still describe pre-#356 geometry, and are now two geometry moves behind.
  No T1 row rests on them, `run_extract_parasitics.py` fails loudly on the
  hash mismatch rather than minting evidence over different bytes, and the
  staleness is disclosed at the top of that directory's README and tracked
  as **#383**.
