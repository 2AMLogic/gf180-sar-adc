- **Note**: ISSUE #282 (RESOLVED): the first attempted run surfaced a genuine, reproducible non-convergence blocker: ngspice did not converge the translated 181-cell sar_ctrl_a gate netlist to a valid digital operating point at all -- even a combinational node whose value is provably unique given the applied stimulus (the OR gate feeding ph0's flip-flop D input, forced high by `start`) settled near 0 V instead of VDD, with only small clk-correlated capacitive ripple, for the whole run. Root cause: the supply net every standard cell binds (`vdd_gate`) is supplied from OUTSIDE the emitted `.subckt sar_ctrl_a` -- nothing inside the subckt drives it -- so without an explicit `.global vdd_gate` declaration, SPICE scoped it LOCALLY to each cell instance, leaving the entire DUT unpowered. `design/sar-logic/flow/gate_netlist_to_spice.py` now emits that `.global` declaration (plus a structural guard, `_assert_external_nets_reachable`, that refuses to emit a subckt where an externally-supplied net would be left locally scoped), and `gen_sar_ctrl_gates_tb.py` re-checks the property on the assembled deck. Validated on a small, standalone, non-closed-loop probe deck (sar_ctrl_a driven directly, no CDAC loop) before this fix landed here: the previously-degenerate node now reads exactly 3.3 V, and vdd_gate itself reads 3.3 V throughout, confirming the DUT reaches a trustworthy digital operating point.
