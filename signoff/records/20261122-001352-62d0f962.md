## Why this record exists

Issue #948 adds the `klt_sim_pin` manifest key: a sha256 over the
canonical JSON of `{"analyses", "measure", "klt_sim"}` that
`harness/batch.py check_exportable` refuses a `klt_sim`-carrying
manifest without, so an edit to either side of the local/batch pair can
no longer drift silently (the refusal names the expected digest).
`sim/comparator-preamp-noise/testbench/tb.json` gained its pin, which
changed the file's bytes and staled item 9's committed analog envelope —
the one envelope `--regen` deliberately never re-mints (#764). The
documented hand step ran under the pinned grader:

```bash
klt signoff --attest 9 --inventory signoff/testbench-inventory.analog.json \
  --format json -o signoff/testbench-inventory.analog.envelope.json
python3 signoff/run_signoff.py --regen
```

The re-attested check run is green; the only pinned hash that moved is
that manifest's (plus the repo-root `README.md`'s current-record
citation re-point below, whose recorded hash is meant to lag). No `sim/`
experiment was re-run, no netlist moved, and the manifest's
`analyses`/`measure`/`klt_sim` content is byte-identical to what the
superseded record pinned — only the new pin key was added.
