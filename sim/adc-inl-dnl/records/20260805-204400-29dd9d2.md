## Methodology note: why this record's `gain_err_lsb` differs from `20260805-163000-e8017f2`'s

`20260805-163000-e8017f2` (PR #96) measured `gain_err_lsb` by driving the
extracted core directly from transition 1's level to transition 1023's level
in a single input step (a ~99.9 %-of-full-scale jump, after only one prior
near-zero-scale conversion) -- a deliberate compute-saving shortcut, stated
explicitly in that record and in `measure_extracted_gain_err.py`'s own
docstring ("narrowly scoped to `gain_err_lsb` only ... NOT the full
18-transition INL/DNL sweep"). It found a consistent **-0.51 to -0.63 LSB**
(mean -0.56) extracted-vs-schematic delta and attributed it to top-plate /
interconnect parasitic-capacitance gain attenuation (#53's finding).

This record reaches the SAME two endpoint transitions (1, 1023) via the
FULL 18-transition ladder -- the same incremental schedule the schematic
baseline itself uses to derive its own `gain_err_lsb` (`tb.json`'s `e1`/
`e1023` come from ONE long transient covering all 18 transitions in
sequence, not an isolated 2-point deck). Measured this way, the
extracted-vs-schematic delta on `gain_err_lsb` collapses to **+0.0028 to
+0.0066 LSB (mean +0.0052)** -- two orders of magnitude smaller, consistently
positive rather than consistently negative, and every
`inl_t*`/`dnl_t*` delta across the full 18-transition set is similarly
small (worst |Δ| 0.043 LSB, see the delta table below), well inside both
the ±1 LSB INL/DNL windows and the noise floor of the two runs' own
corner-to-corner scatter.

**Root cause, verified by diffing the two composed decks byte-for-byte**
(`sim/adc-inl-dnl/netlist-snapshots/20260805-163000-e8017f2.spice` vs
`sim/adc-inl-dnl/netlist-snapshots/20260805-204400-29dd9d2.spice`): the two
decks are IDENTICAL except for the input PWL schedule and the transient
stop time / measure statements -- same extracted-core subcircuit text, same
remediation, same comparator/controller/input-network wiring, same shadow-DAC
formula. The only circuit-relevant difference is that `e8017f2`'s deck asks
the ~1300-device RC-laden extracted core to settle from a near-zero-scale
DAC state to a near-full-scale DAC state in ONE step, after only one prior
conversion's worth of internal-node equilibration; this record's deck visits
every intermediate major-carry transition first (the largest single step
anywhere in the 18-transition ladder is 896→1022, ~126 LSB / ~12 % of full
scale -- about 8× smaller than `e8017f2`'s one-shot ~1022 LSB jump), so by
the time transition 1023 is probed, the extracted core's internal RC network
has already been carried up through the code range incrementally. The
schematic core shows no such sensitivity (its wires are ideal, so a big
one-shot step settles just as fast as a small one), which is why
`e8017f2`'s shortcut methodology was invisible on the schematic side and
only surfaced once it was pointed at the RC-laden extracted netlist.

**Disposition**: `20260805-163000-e8017f2` is NOT edited or deleted
(append-only, per `sim/README.md` / CLAUDE.md) -- it remains valid evidence
of the extracted core's step response to an artificially large, atypical
one-shot full-scale input transition (a real, if narrow, large-signal
settling characterization, not an error). **This record is the
methodologically apples-to-apples comparison against the schematic
baseline's own `gain_err_lsb` derivation** (same schedule, not just the same
two endpoint transitions and formula) and is the number to use for the
schematic-vs-extracted delta summary's Gain-error row and for #53's
adjudication. `layout/adc-top/parasitics/README.md` is updated to point
readers at this record for that purpose; see "Supersedes" below.
