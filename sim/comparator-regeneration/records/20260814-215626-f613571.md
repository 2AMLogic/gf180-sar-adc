  `ADC_BLOCK` core**, with #9's 0.5 LSB / 100 mV / 0.1 mV overdrive ladder

  rather than to 0 V. Manifest thresholds (`sim/comparator-regeneration/
  testbench/tb.json`) are quoted, unmodified — this record is NOT produced by

  copied from it verbatim.

- **Why a bespoke script, not `sim/run_corners.py`**: the schematic deck
  (`tb_regeneration.spice`) instantiates three parallel, independently-supplied
  comparator subckt copies (A/D/E) and forces `vinp`/`vinn` directly; a
  comparator-inclusive `ADC_BLOCK` core cannot be tripled that way without
  needlessly tripling an already-large extraction's device count, and there is
  no clean per-comparator supply node on the shared array rails to integrate
  current on. `layout/adc-top/parasitics/measure_extracted_regeneration.py`
  instead drives **one** `Xdut ADC_BLOCK` instance sequentially through all
  three overdrive steps, forcing `topp`/`topn` directly (the comparator's own
  input pins, loaded by the REAL extracted CDAC array sitting on those nodes,
  every array control net held at a fixed one-hot DR-0014 decode) — see that
  module's own docstring for the full methodology and why sequential reuse of
  one instance is electrically legitimate (the StrongARM latch precharges
  every `cmpclk` low phase, same as ten successive real bit trials).
- **Why the ladder is offset-referred, not 0 V-referred (a new, measured
  finding)**: the first working run of this deck (nominal corner) found the
  naïve, 0 V-referenced 0.5 LSB decision **stuck** — a nominal −0.5 LSB
  (−1.6113 mV) differential still decided HIGH. Direct measurement
  (`measure_offset()`: a slow `topp`−`topn` ramp with `cmpclk` free-running,
  `.meas … find v(vda) when v(dout_norm)=0.5`) explains why: the extracted
  core carries a real, **deterministic** systematic input-referred offset —
  measured at every one of the 45 corners below, ranging **−0.597 … −4.357 mV**
  — bigger than the half-LSB overdrive itself at every corner, well inside
  the ratified `≤ 2 LSB` (12.89 mV) 3σ **mismatch** bound
  (`sim/comparator-offset-mc/`), but enough to swallow #9's 0 V-referenced
  ladder. This is a genuine post-layout finding, not a bug worked around
  silently: no statistical mismatch is enabled anywhere in this deck (same
  nominal device geometry as the schematic, `sw_stat_mismatch` untouched), so
  a nonzero offset can only be a **deterministic** asymmetry the drawn
  layout's real interconnect between the `topp`/`topn` block-boundary pins
  and the preamp's actual gates introduces — something no schematic-level
  deck can show by construction. Per CLAUDE.md ("report FAIL and escalate
  rather than silently adjusting"), the honest response is to measure the
  offset per corner and refer the ladder to it, not to pretend the extracted
  core is still offset-free the way the schematic's by-construction-symmetric
  deck is.
- **Offset-measurement resolution, and its one consequence (stated, not
  hidden)**: `dout` only updates once per `cmpclk` strobe (62.5 ns), so the
  ramp-based offset search is quantised to how far the ramp moves in one
  strobe period — `2 × 20 mV / (2000 ns / 62.5 ns) ≈ 1.25 mV` — not the
  ~40 µV a naïve read of the transient's 2 ns print step would suggest
  (every `vos_v` value below visibly lands on one of a small set of
  ~1.25 mV-spaced values). That is still >10× finer than the 0.5 LSB
  (1.6113 mV) / 100 mV overdrive steps the ladder needs to land cleanly on
  either side of, which is why `td_half_ns`/`td_big_ns`/`margin_ns`/`tau_ps`
  resolve at **all 45/45 corners**. It is roughly **an order of magnitude
  coarser** than the 0.1 mV (`dv_tiny`) metastability probe, which is why
  that probe does **not** resolve at any corner here — see "Metastability
  probe" below. This is a stated measurement-resolution limit, not a hidden
  one.
