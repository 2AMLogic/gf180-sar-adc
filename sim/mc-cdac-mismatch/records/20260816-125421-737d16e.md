# Record 20260816-125421-737d16e

- **Record ID**: 20260816-125421-737d16e
- **Claim**: `README.md#target-specification` — **Gain error, mismatch**, ≤ 0.5
  LSB, untrimmed, excluding V_REF error, 3σ Monte Carlo mismatch (**not** a
  PVT corner). This record verifies the **resized** unit-cap sizing decision
  issue #177 makes (`spec/decision-records/
  DR-0019-cdac-unit-cap-resize-for-gain-error-margin.md`, `spec/cdac-sizing-memo.md`
  §3.6/§4) — `σ_u = 0.5000 %` (`C_u = 35.6528 fF`, `s = 4.0 µm`), **not** the
  design's currently-drawn `σ_u = 0.7372097807744856 %`
  (`C_u = 17.24 fF`) that `sim/mc-cdac-mismatch/records/
  20260816-044942-56fbe50.md` (issue #172) measured failing at 2.12σ. This
  record does **not** supersede that one — the built design has not changed
  yet (`design/adc-top/gen_adc_top.py`'s `C_UNIT_FF` and
  `layout/adc-top/`'s `UNIT_CAP_NM` still carry the historical value pending a
  physical-implementation follow-up, see `spec/cdac-sizing-memo.md` §4's
  "Chosen unit cap" note) — this is new evidence for a **proposed** resize,
  using the same standalone Monte Carlo mismatch model this repo already
  relies on for every matching-based claim in this row (the PDK ships no
  local capacitor mismatch model at all, so no netlist-level re-simulation
  would add information the calibrated behavioral model does not already
  give — `mc_cdac_mismatch.py`'s own module docstring).
- **Netlist provenance**: none — behavioral model
  (`sim/mc-cdac-mismatch/testbench/mc_cdac_mismatch.py`, unmodified from
  issue #172's version — this record changes only the `--sigma-u` input, not
  the script). Taken against a clean working tree at commit
  `737d16ec96b2b1d1cfe017abfd85d59abd1d3fba` (`git status --short` empty before this record's own files
  were added) on `feature/issue-177`.
- **Corner matrix run**: nominal only — same "Subset-corner justification" as
  every prior campaign in this directory (`sim/mc-cdac-mismatch/records/
  20260801-093800-c033611.md`, `.../20260816-044942-56fbe50.md`): a
  device-mismatch statistical claim is evaluated at nominal PVT, not swept,
  because process variation cancels exactly in the array's own capacitor
  ratio (`spec/cdac-sizing-memo.md` §5.3, `spec/testbench-suite-memo.md` §6).
- **Statistical convention**: `N = 20000`, `seed = 20260801` (same seed as
  every prior campaign in this directory, for direct comparability),
  `sigma_u = 0.5 %` (the resized design's calibrated Pelgrom coefficient,
  `A_C / s = 2.0 %·µm / 4.0 µm`, `spec/cdac-sizing-memo.md` §4) for the
  nominal draw.
  - **Negative control** (real simulation, not synthetic): the resized
    design's unit-cap mismatch sigma forced to **3×** its calibrated value —
    `sigma_u = 1.5 %` — via `mc_cdac_mismatch.py --sigma-u 1.5 --trials 2000
    --seed 99109901`, the identical methodology and seed issue #172 used for
    its own gain-error negative control. Raw output:
    `sim/mc-cdac-mismatch/runs/20260816-125421-737d16e/trials_n2000_3xsigma.csv`,
    `summary_n2000_3xsigma.json`.
  - **Analytic cross-check**: `klt yield`'s `mismatch_offset` model, fed
    `sigma = analytic_sigma_gain_lsb = √1024 · σ_u / 100 = 0.16` LSB, the
    closed-form total-array prediction `mc_cdac_mismatch.py` computes
    directly at this `σ_u` (`ANALYTIC_GAIN_COEFF = √1024`,
    `spec/cdac-sizing-memo.md` §3.6).

  **DNL/INL re-confirmed to still pass at this `σ_u`** (per issue #177's
  Acceptance Criteria: a resizing pass must re-state, not assume, DNL/INL
  margin — `spec/cdac-sizing-memo.md`'s Non-goals only assert this "should"
  hold, not "does"). From the same nominal N=20000 run's own summary JSON
  (`sim/mc-cdac-mismatch/runs/20260816-125421-737d16e/summary_n20000.json`):

  | Measurement | 1σ (measured) | 3σ | vs. ratified target | Margin |
  |---|---|---|---|---|
  | `dnl_at_256_lsb` | 0.113447 LSB | 0.340340 LSB | < 0.5 LSB (stretch) | `meets_target_sigma: true`, `sigma_at_spec = 4.407` |
  | `inl_at_256_lsb` | 0.056723 LSB | 0.170168 LSB | < 0.5 LSB (stretch) | `meets_target_sigma: true`, `sigma_at_spec = 8.815` |

  Both clear the **stretch** (0.5 LSB) target, not merely the 1.0 LSB
  baseline, confirming `spec/cdac-sizing-memo.md` §3.6's prediction that
  sizing to the gain-error constraint satisfies DNL/INL "with room to
  spare" — quantified here, not assumed.

  **Why the resized `σ_u` clears 3σ where the historical `σ_u` did not.**
  `sim/mc-cdac-mismatch/records/20260816-044942-56fbe50.md` measured the
  historical design's `σ_u = 0.7372 %` at `2.122σ` against the same 3σ
  target — a genuine gap, not a testbench defect
  (`spec/cdac-sizing-memo.md` §3.6 traces it to a wrong-coefficient sizing:
  `C_u` was sized to DNL/INL's own `σ_u ≤ 0.737 %` requirement, not gain
  error's tighter `σ_u ≤ 0.521 %`). This record's `σ_u = 0.5000 %` is below
  that `0.521 %` exact-boundary ceiling with a deliberate margin (not merely
  at the boundary — `spec/cdac-sizing-memo.md` §4 explains why an
  exact-boundary sizing was rejected: a first attempt at `σ_u = 0.520833 %`
  measured only `3.009σ`, uncomfortably close to a repeat of this exact
  finding — see "Rejected exact-boundary alternative" below), and this run's
  `sigma_to_spec = 3.1306` shows the resulting real, not-knife-edge margin.

  **Rejected exact-boundary alternative** (not this record's chosen design,
  kept here for the record since it was actually run): `mc_cdac_mismatch.py
  --sigma-u 0.5208333333333334 --trials 20000 --seed 20260801` (the
  `σ_u` that inverts `spec/cdac-sizing-memo.md` §3.6's formula to exactly
  `3σ = 0.5` LSB, `C_u = 33.004 fF`, `s = 3.84 µm`) measured
  `sigma_to_spec = 3.009`, `meets_target_sigma: true` but by a margin
  statistically indistinguishable from the boundary this whole issue exists
  to move away from. Not saved as its own run directory (superseded by the
  chosen `s = 4.0 µm` sizing before being promoted to evidence); the raw
  JSON is reproducible from the command above and is quoted directly in
  `spec/cdac-sizing-memo.md` §4.
