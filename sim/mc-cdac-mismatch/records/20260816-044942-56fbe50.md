- **Script change**: `mc_cdac_mismatch.py` is extended (not replaced) to
  additionally compute a `gain_error_lsb` per-trial quantity. Gain error is
  a TOTAL-array-capacitance effect, not a code-dependent DNL/INL one
  (`spec/cdac-sizing-memo.md` §5.2: `C_total = 2·C_side = 1024·C_u`, both

  dummy each) — architecture-invariant 1/√1024 averaging, **not** the split
  topology's √511 / (√512)/2 DNL/INL coefficients, which benefit from the
  free-MSB property (`spec/cdac-sizing-memo.md` §3.1-3.2) that gain error
  does not. The extension draws the 513 additional per-trial unit-cap
  mismatches (this side's own dummy, deliberately excluded from the DNL/INL
  model per the module's own docstring because it is a common term in every
  code's denominator rather than a DNL/INL error — but IS a real gain-error
  contributor; plus the mirror side's full 512-unit sub-array) **after**
  every draw the existing DNL/INL computation consumes, from the same
  seeded RNG stream, so `dnl_at_256_lsb`/`inl_at_256_lsb`/`max_dnl_lsb`/
  `max_inl_lsb` are unperturbed.

  **Why this differs from note [e]'s 0.049 % / 0.5 LSB figure.** README
  note [e] computes `3 × 0.52 % / √1024 = 0.049 %` using
  `sim/device-characterization-report.md` §5.1's **binding requirement**
  `σ_u ≤ 0.52 %` — the ceiling the *plain-binary, generic* array model
  needs to hit the *DNL* stretch target, computed at spec-ratification time
  before DR-0011's split topology was chosen. The chosen design's *actual*
  calibrated `σ_u = 0.7372 %` (`spec/cdac-sizing-memo.md` §3.4) is **larger**
  than that ceiling — it was sized against the split topology's own,
  looser-by-√2 DNL coefficient (§3.2's `√511`, not the generic `√1023`), not
  against the gain-error mechanism, which does not benefit from the split
  topology at all (§5.2's `C_total = 1024·C_u` sum is architecture-
  invariant). Substituting the actual `σ_u` into note [e]'s own `3σ_u/√1024`
  formula gives `3 × 0.7372 % / 32 = 0.0691 %` of full scale = **0.708 LSB**
  analytically (`analytic_sigma_gain_lsb × 3 = 0.235907 × 3 = 0.708 LSB`) —
  matching this record's own measured `2.122σ` finding (`measured stddev
  0.235185 LSB × 3 = 0.706 LSB`, within 0.3 % of the analytic prediction,
  the same `analytic cross-check: consistent` row `klt yield` reports
  above). **Note [e]'s
  0.5 LSB figure was never the chosen design's actual performance; it was
  the ceiling a *different*, unbuilt design would need.** This is not a
  testbench defect and not evidence of a wiring bug: it is the first time
  this row has been checked against real per-trial data rather than a
  closed-form ceiling, and the honest result is a genuine near-2× miss
  (`0.708` vs `0.5` LSB, `2.12σ` vs the `3σ` target), reported exactly as
  measured per `CLAUDE.md`'s "no claim without a testbench" / "agents do not
  relax the ratified spec to make results pass". **No spec value is
  relaxed here and no design change is made** — this record's scope is
  evidence-format-and-honesty (issue #172, T1 item 6), not a resizing.
  Flagging the row for a real resizing pass (larger `C_u`, or a design that
  trades DNL/INL margin for gain-error margin) is left to a follow-up issue;
  see "Links" below.
