### Reading it

1. **At `hold1` — the instant the superseded record reads — the schematic core
   reproduces the "extracted" number.** −2.5570 / −2.5918 / −2.5388 LSB on a
   core with *zero* parasitics, against −2.5601 / −2.5946 / −2.5406 LSB
   extracted: an extracted-minus-schematic difference of **−0.0018 to −0.0032
   LSB**, i.e. within noise of zero. Record `20260805-163000-e8017f2`'s
   −2.52 … −2.63 LSB is therefore a property of **its stimulus**, reproducible
   without any layout at all.
2. **By `hold2` both arms have collapsed onto ≈ −1.99 … −2.01 LSB** — the
   schematic baseline's own value (`20260802-141402-1224e11`) and the
   like-for-like extracted value (`20260805-203322-3b6d7b7`), to within
   0.02 LSB. The endpoint is simply **not settled one conversion after a
   near-full-scale step**.
3. **The extracted-minus-schematic delta is ≤ 0.004 LSB at every hold length
   and every corner** (full 8-row tables in the committed JSON). Whatever
   top-plate/interconnect parasitic the layout adds, it is not resolvable at
   this measurement's precision — consistent with the +0.006 LSB the
   27-corner like-for-like run reports, and inconsistent with −0.55 LSB.

### The mechanism, stated so it is falsifiable

`measure_extracted_gain_err.py` drives a **two-point** ladder: the input goes
from transition 1 straight to transition 1023 — a ~1022 LSB, near-full-scale
step — and the endpoint is read inside that single `CONV_NS = 1000 ns`
conversion. The 18-transition `adc-inl-dnl` manifest always arrives at 1023
from 1022, by a **1 LSB** increment, after seventeen prior settling
conversions. The schematic bench's own deck header anticipates exactly this
failure mode: it argues its largest 126 LSB step leaves 126·e⁻¹⁰ ≈ 0.006 LSB
of residual acquisition error — an argument that does not survive being
stretched to a 1022 LSB step through an RC-laden input network on the same
1000 ns budget.

The probe was designed to be able to say "no": if `e1023` had been **flat**
across the hold, step size would *not* have been the explanation and the
script says so. It is not flat — it moves 0.56 LSB between hold 1 and hold 2
and then ≈ 0.02 LSB peak-to-peak thereafter — and it moves the same way on
both cores.

**One honest residual.** After `hold2` the tail alternates by ≈ 0.02 LSB with
hold parity (odd holds ≈ −0.986, even holds ≈ −0.968 LSB at `tt_27c_2.97v`).
That is a second-order ripple of the held stimulus, an order of magnitude
below the 0.56 LSB effect under test and present identically on both cores, so
it does not bear on this record's claim; it is recorded rather than smoothed
away.

  python3 layout/adc-top/parasitics/probe_gain_err_settling.py \

~28–40 s per run on an idle 8-core host (extracted arm is the slower one).

outside `sim/*/corners/`, and each run's log is megabytes of repeated
operating-point node dumps for a ~1300-device netlist. Every number above is
in the committed JSON, and the decks regenerate deterministically from the
committed generator plus the committed extraction.
