# Record 20260801-093800-c033611

- **Record ID**: 20260801-093800-c033611
- **Claim**: `README.md#target-specification` — INL / DNL, < 1 LSB baseline
  (ratified) / < 0.5 LSB stretch (aspirational), untrimmed, 3σ Monte Carlo
  mismatch (not a PVT corner). Consumes the yield criterion (3σ) and array
  topology (DR-0011, 511-unit-cap sub-array) from `spec/cdac-sizing-memo.md`
  §3.1–§3.3, the calibration (`A_C = 2.0 %·µm`, chosen `A_unit = 7.36 µm²`)
  from §2/§4 of the same memo, and reports against both target rows. Full
  methodology and interpretation: `spec/monte-carlo-methodology-memo.md` §2.
- **Netlist provenance**: **behavioral, not ngspice.** The gf180mcu open PDK
  ships no local capacitor mismatch model (`cap-local-mismatch` /
  `moscap-statistics` both `ABSENT`, `sim/device-characterization-report.md`
  §5.1 / `sim/tools/pdk_mismatch_audit.py`), so an ngspice Monte Carlo of the
  CDAC array would report exactly zero mismatch at any trial count — a
  silent false pass. `README.md#target-specification`'s own text permits a
  "behavioral CDAC model calibrated to extracted unit-cap sigma" for exactly
  this reason (issue #14). This record's tool is
  `sim/mc-cdac-mismatch/testbench/mc_cdac_mismatch.py`, a standalone
  Python/NumPy/SciPy script — not invoked through `sim/run_corners.py`
  (there is no netlist to run), so it is not covered by the harness's
  toolchain-pin / dirty-tree machinery. Reproducibility instead rests on:
  the script's own committed source at git commit `c033611` (this record's
  git-sha component), the fixed RNG seed below, and the calibration inputs
  cited (not re-derived) from `spec/cdac-sizing-memo.md`.
- **Corner matrix run**: nominal PVT only (no PVT axis — mismatch is
  evaluated at nominal by construction; the calibration itself,
  `A_C = 2.0 %·µm`, is a single literature-derated PDK-independent
  coefficient, not something this record sweeps over process/temp/supply).
  **Subset-corner justification**: this is a device-mismatch statistical
  claim, not an environmental one — see `spec/monte-carlo-methodology-memo.md`
  §4 for the explicit division of labor against #13's nominal-design PVT
  corner verification, and `sim/cdac-bit-settling/` §5.3's independent
  finding that global process variation cancels exactly in the CDAC's
  charge-division ratio, which is the quantitative reason a nominal-PVT-only
  mismatch sweep is valid here.
- **Statistical convention**: fit-and-extrapolate (not empirical
  tail-counting) — `N = 5000` trials fit to a Gaussian at the
  analytically-worst code (256), yield computed analytically from the
  fitted σ at the target sigma level. A brute-force count of 3σ/6σ tail
  events is intractable at any trial count this record could run (2-sided
  tail probability `2.7e-3` / `2e-9` respectively); see
  `spec/monte-carlo-methodology-memo.md` §2.4 for the full justification.
  - **Seed handling**: `numpy.random.default_rng(seed)` (PCG64),
    `seed = 20260801`. Fully reproducible:
    `python3 sim/mc-cdac-mismatch/testbench/mc_cdac_mismatch.py --sigma-u
    0.7372097807744856 --trials 5000 --seed 20260801`. Independent RNG
    stream from any ngspice `setseed` used elsewhere in `sim/` — this
    script never invokes ngspice, so there is no shared-state hazard.
  - **Scope**: mismatch-only (`σ_u` per unit capacitor; no global/process
    term — a die-global capacitance shift cancels exactly in the array's
    charge-division ratio, `spec/cdac-sizing-memo.md` §5.1 /
    `README.md` note **[e]**).
  - **Sigma level**: 3σ, consumed from `spec/cdac-sizing-memo.md` §3.3 —
    not independently chosen here.
- **Linearity methodology**: `full-1024-code-ramp`-equivalent for the
  sub-array — every trial evaluates the full 512-code transfer function of
  the 9-bit sub-array (all 511 DNL transitions, all 512 INL points), not a
  reduced/major-carry-only code set. Bit 1 (the free MSB) is excluded by
  construction (zero mismatch — a sampled-charge sign decision, not a
  charge-redistribution ratio, `spec/cdac-sizing-memo.md` §3.1).
  End-point-corrected INL definition used throughout.

  **Overall: PASS against the ratified baseline (< 1 LSB)**, on both DNL
  and INL, with ~6σ / ~12σ margin respectively. DNL is the binding
  constraint, as `spec/cdac-sizing-memo.md` §3.5 predicts.

  **Stretch-target caveat (< 0.5 LSB, aspirational, not the ratified row):**
  DNL's 3σ figure (2.979σ at N=5000, 2.989σ at the N=20000 cross-check) is
  formally just short of the 3.0σ line, but `spec/cdac-sizing-memo.md` §4
  sized the unit cap by *inverting* the 3σ condition against this exact
  target — by design there is ~zero margin here. This record's own
  statistical precision at N=5000 (`1/√(2N) ≈ 1.0 %`) exceeds the 0.7 %
  shortfall observed, so the correct reading is statistically
  indistinguishable from exactly meeting the stretch line, not a real
  shortfall (confirmed by the N=20000 cross-check moving closer to 3.0, as
  expected). Stated plainly per CLAUDE.md's rule against relaxing a claim
  to make it look better than it measured. Full derivation:
  `spec/monte-carlo-methodology-memo.md` §2.7.

  **Secondary, explicitly non-Gaussian bound — max-over-all-codes
  statistic** (reported, not used for extrapolation): the trial's actual
  `argmax|DNL|` / `argmax|INL|` over all 511/512 points is a maximum of
  several near-degenerate-variance, correlated Gaussians (Shapiro-Wilk
  strongly **rejects** normality: DNL `W=0.9628, p=5.2e-34`; INL
  `W=0.8969, p=1.0e-49`) — an extreme-value-type distribution, not itself
  Gaussian, exactly the goodness-of-fit-deviation edge case issue #14's
  test plan requires be flagged rather than silently extrapolated through.
  Reported as a no-fit empirical bound only: `N=5000` empirical 3σ
  (`3× sample σ`) of max|DNL| = 0.577 LSB, max|INL| = 0.409 LSB; single
  worst observed trial 0.634 LSB (DNL) / 0.360 LSB (INL). All consistent
  with, and slightly more conservative than, the code-256 figures above.
