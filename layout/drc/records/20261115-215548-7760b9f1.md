`deck_scope` sections**. The 0.8.0 reports print **114 rules over 16 sections**;
the six added sections are exactly `7.8 Nplus`, `7.9 Pplus`, `ESD`, `GR`,

- `contact.width.1` is **not** in the added set: it was in `rules_checked` at

### `comp.coverage.1` — implants on taps only (DRM 7.5 DF.12)

Rule: "COMP not covered by Nplus or Pplus is forbidden", limit = full coverage
(no distance). Sampled marker (`adc_block`, cell `ADC_DECODE_BANK_P`): the
entire uncovered Comp region of one decode bank, polygon (0, 0)-(2550, 4000)
nm at dbu 0.001 — no implant anywhere on the S/D diffusion, because
`layout/adc-top/lib/geometry.py:130-142` draws `Pplus`/`Nplus` only on taps
with the voided rationale quoted in #836. The `sw_unit` sample is the same
story in miniature: the proof cell draws only Comp/Poly2/Contact/Metal1
(`gen_sw_unit.py`), so its whole 3.0 x 1.2 um Comp rectangle fires.

### `contact.width.1` — the CO.1 exact-size half is now enforced

Rule (0.8.0 description string): "min/max contact size (fixed 0.22 x 0.22 um
square)" — **min and max**, limit 220 nm both ways. Traced in the 0.8.0 deck
source (`klayout_tools/decks/gf180mcu.py`): `threshold_dbu=220` plus
`threshold_max_dbu=220`, the max measured as a bounding-box size so over-long
*bars* are caught (upstream klayout-tools#2370; the 0.6.0 deck enforced only
the min half, as this repo's own `geometry.py:80-89` documented). Sampled
marker (`adc_block`, cell `ADC_DECODE_BANK_P`): a source/drain Contact **bar**,
polygon (190, 150)-(450, 3850) nm = **260 x 3700 nm** against the fixed
220 x 220 square — legal under a min-only check, illegal under CO.1. This
**confirms** the mechanism #797's curation marked "inferred, not traced"; the
follow-up (#837) re-draws the S/D bars as arrays on the tap-array precedent
(issue #356) and rewrites the voided prose.

### `poly2.enclosing.sab.1` / `sab.space.1` — the resistor markers (DRM SB.10 / SB.2)

- `poly2.enclosing.sab.1`, limit: Poly2 must extend **220 nm** beyond the
  related SAB. Measured on the committed `comparator.gds` (klayout API): each
  SAB marker is **exactly coincident with its Poly2 body** -- both bboxes
  `(94050,700)-(99850,37750)` -- extension **0 nm**. Sampled marker: the
  deficient edge, bbox (572750, 64140)-(572750, 101410) in `adc_block`
  coordinates (a degenerate polygon; see klayout-tools#5869). `place.py`'s
  `draw_poly_resistor` drew the markers "exactly the size of `body`" because
  the pinned deck carried no SB rule -- voided now.
- `sab.space.1`, limit **420 nm** SAB-to-SAB. Measured: the two resistor SAB
  bodies sit **400 nm** apart (left body right edge 99850, right body left
  edge 100250). Sampled marker: the gap region itself, polygon
  (578550, 64360)-(578950, 101410) in `adc_block` coordinates.
- Fix (one layout change, keeping the `poly2.and(sab).…` extraction
  derivation and the drawn-area identity intact): #838.

### `*.ongrid.1` — real off-grid vertices in `adc_top.gds` only (PDK OFFGRID group)

Rule: "vertices must be on the 0.005um manufacturing grid", one rule per
curated layer (the whole `OFFGRID` section is new; grid literal 0.005 on every
call site). Verified **independently of the deck** (flat `klayout.db` read of
both GDS files, top-cell coordinates):

- `adc_top.gds`: every marker is a real off-grid vertex, all in `ADC_TOP`'s
  **own top-cell shapes** (identity placement), **x mod 5 in {1, 3} nm, y
  always on-grid** -- 771 Contact squares (each exactly 0.22 x 0.22 um; e.g.
  left x = 584776 = 5k+1) making 3084 vertices/markers, plus the right-side
  guard-ring strapping (Comp, Metal1, Pplus; e.g. x = 625033 = 5k+3).
  Sampled markers: `contact.ongrid.1` at (459976, 136290); `metal1.ongrid.1`
  at (621633, 141100); `comp.ongrid.1` at (623633, 137100); `pplus.ongrid.1`
  at (623473, 137260) -- all x = 5k+1 or 5k+3, deck marker count consistent
  with the independent vertex count per layer.
- `adc_block.gds` (same `build()` in `gen_adc_top.py`): **zero** off-grid
  vertices on those layers -- its own top-cell 220 nm contact squares are all
  x mod 5 == 0. The defect is localized to the adc_top-side top-level drawing
  math (the `// 2` centring computations such as `top_plate_exit_x()`); fix
  and evidence in #839.
