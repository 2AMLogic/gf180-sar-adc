## Why this record exists

Issue #437 added `sim/tools/check_characterization_summary.py`, a stdlib-only
check run by `npm run check:ci` and headless CI. It checks the `Source (dated)`
column of `sim/characterization-summary.md`'s per-spec-row table. Every
sim-record link in that column now carries a citation-local
`<!-- evidence role=… mode=… -->` marker (64 links). A `governing` or `current`
citation fails if a same-mode record supersedes it, or if a newer same-mode
record of its campaign is neither linked in the row nor covered by an exact,
reasoned entry in `sim/tools/characterization_citation_exceptions.json`.

The first run found three currency defects in the summary. All three were fixed
from committed records, with no new simulation:

1. The `Supply` row had an unescaped `|Δ|` that split it into 7 table cells.
   GitHub renders 5, so the row's real Verdict and Source cells were hidden.
2. The `INL / DNL` row's 3σ mismatch figure was the pre-resize `σ_u = 0.737 %`
   one (5.96σ / 11.9σ). It now quotes the as-built `klt yield` figures
   (8.812σ / 17.627σ against ±1 LSB), with the old figures kept as history. The
   row also called the PR #149 bundle pre-resize, which its own record
   contradicts for DNL/INL; that sentence is corrected.
3. The `V_CM` row now cites `20260924-041435-cda7de5`, the issue #395 successor
   of the superseded power arm `20260923-114021-836a876`.

`sim/characterization-summary.md` is the hash-pinned source of both item-8
envelopes, so editing it forces a re-mint:

```
sha256:aa560659...dec5a6   ->   sha256:0e834650...5074d  (full: sha256:0e834650eefd129d0b49942d2313cc945acd77ff6e48d990912e5a6691a5074d)
```

## The item-8 re-read, and what it was not

Both envelopes (`signoff/evidence/characterization-summary.{analog,digital}.json`)
gained a seventh `partial_updates[]` entry and the new `content_hash`. The
analog envelope's `known_gaps_carried` line saying there was "no klt yield
envelope of the INL/DNL row at DR-0019's built C_u" was corrected in place, with
its old wording quoted, because it was the same false claim as defect 2 above.
**This is not a new row-by-row re-read against `README.md#target-specification`.**
`reread_commit` (`93ddfe3`) and `reread_date` are deliberately not bumped, as in
the five prior partial updates. The classification of every Source-column
citation and every newer same-campaign record the check surfaced was done from
the records' own provenance fields. The 28 resulting exceptions each name one
row, one mode, one cited record and one newer record. Two of them rest on
follow-ups rather than resolutions: #459 (the #393 gain-error ideal arm does not
bit-reproduce its citation) and #460 (the `Clock` row's record predates #371's
deck correction).
